Fifteen worked examples

Every span below came from the real library. The page is generated by site/gen_data.py and site/build.py, and the build fails if a single recorded offset breaks source[start:end] == text. There is no hand-written result on this page.

note
Every string is fake. Do not replace one with production text. Examples 10 to 14 need a model lane, because a name, an address, a national id, and a login name have no grammar a rule can own.

How to read a block

FieldMeaning
SourceYour string, with each span marked. Hover a mark for its offsets.
ResultThe span table. ok means the recorded slice equals the recorded text.
Score1.00 means a checksum confirmed the slice. — means no validator exists for that form.
MaskedThe same string with placeholders in place of spans.
VaultPlaceholder to original slice. A secret never appears here.

6 Text with no PII

Lane rules · no span

These look numeric, and none is a published PII form. A locator that spans them is guessing.

Source

Order 48291 ships as SKU-77219 from warehouse 4. The build finished in 12 minutes on node 3.

Result

No span. Nothing in this text matched a grammar on this lane, and that is the correct answer. A locator that invents a span here would be useless.

Masked output

Order 48291 ships as SKU-77219 from warehouse 4. The build finished in 12 minutes on node 3.

Vault

The vault is empty. A secret never enters it, and this text holds none.

What these examples do not prove

An example shows that one string works. It does not measure accuracy. A library can pass every string on this page and still score badly on a new domain, and that is exactly what the public score found: the closed encoder's person score falls from 0.995 in domain to 0.048 on finance text.

Use these pages to understand the shape of a result. Use the evaluation guide to decide whether the library is good enough for your text.
